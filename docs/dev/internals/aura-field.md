# 光环场内部机制

## 1. Interface 与状态归属

`BlockAuras` 按实际 `ServerLevel` 实例拥有瞬态 `BlockAuraField`。源回调、区块事件与查询在服务端主线程串行执行，源坐标使用 packed long，区块卸载时根据源所有权移除覆盖。世界卸载与服务器停止释放引用，存档方块状态是恢复索引的事实源。

`hasEffect` 查询格子上的能力；`blocksEntry` 查询移动线段是否入区。两者共同消费内存覆盖索引，查询不获取区块或读取方块。实体保护与移动参考点采用脚部位置。立方体在每轴覆盖源坐标前后 8 格，连续空间按这些格子的半开区间处理。

区外起点遇到覆盖即拒绝；区内起点允许穿过起始连续覆盖并离开，离开后再次入区则拒绝。该 Interface 同时服务地面候选边与 AI 推进判定，使内部已有怪物可以自行离开。

## 2. 源索引与懒覆盖

光环源按所属 chunk 索引，并登记到立方体相交的 section。每个 section 桶保存影响它的源，按需生成覆盖 `BitSet`。重复登记和移除保持幂等；更新仅失效相交桶，桶失去全部源时直接释放。

重建使用三维差分：将每个源裁剪到 section，通过立方体角点写入差分，沿各坐标轴累加得到覆盖，再转换为位图。重建成本为 `O(s + v)`，其中 `s` 为影响该 section 的源，`v` 为 section 体积。重叠源由计数自然合并，移除源后重建并集，避免清除其他源覆盖。

有效缓存下，单点查询为一次 section 查找和位查询。连续源变化合并至下一次读取前；读取之后的源变化重新失效，下一次决策获得当前覆盖。

线段查询使用分层 DDA，空 section 整段跳过，有源 section 按穿过的格子查询。其成本随线段穿越范围增长，遇到禁止入区即结束。区块加载通过 `ChunkAccess.findBlocks` 先筛选 section 调色板，仅枚举可能含源的 section。

## 3. 移动与动作接入

地面路径请求在原版复用旧路径之前过滤目的地；`GroundPathNavigation` 调整目的地高度之前也检查原始坐标。A* 过滤候选边，使原版寻路继续负责地形和绕行。

navigation 提交 waypoint 时复核移动段。地面在 `Entity.moveRelative` 写入速度时、跳跃在原版跳跃写入点复核新推进；NeoForge 的液体跳跃经扩展入口单独接入。Adapter 提供写入前的携带速度与原版拟写入速度，拟定移动段入区时撤回此次 AI 贡献。光环与目标变化在后续决策中重新查询。

幻翼保留原版飞行控制，在控制器写入速度时复核。受阻时按与原贡献的接近程度选择有限轴向贡献，并检查携带速度加候选贡献后的完整线段；全部受阻时保留携带速度。盘旋备用目标使用有水平距离的固定方向，供原版控制器执行；无候选时返回当前位置，让原版接近目标条件参与重选。备用落点先检查涉及区块已加载，再检查碰撞。

速度决策只限制新主动推进，最终 `move` 继续由原版消费速度。已有惯性、重力、击退、水流、传送与活塞保持原版处理，可能把怪物带入区域。`NoAI` 与客户端跳过推进约束。

`AuraRepulsion` 统一处理受保护目标与自然蓄爆；`SwellGoal` 的缓存目标单独复核，人工点燃例外也归属该普通类。幻翼俯冲读取目标时解除受保护目标，由原版停止逻辑复位攻击阶段。生成玩家筛选在失眠判定前组合旁观者、猫之威慑和玩家脚部光环；猫族能力缓存仍由猫族关系子系统维护。

## 4. 效果扩展

成熟植株与盆栽共用 `BlockAuras` 的范围和 `AuraEffect` 集合，位图表达它们共同覆盖的区域。新增同范围效果时，在集合中声明能力，并在消费它的玩法决策处调用 `hasEffect`。光环场本身不负责驱动全部实体或逐源 tick。

受驱避类型和对应移动 Adapter 共同维护。新增移动机制时先接入其实际决策与 AI 推进写入点，再将该类型加入驱避判定。
