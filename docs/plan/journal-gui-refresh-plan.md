1. `ScenarioDetailPanel.java:156-165` 逐处摆放标题、图标按钮和框；`JournalLayout.java:54-56` 固定场景框顶边与高度。改信息层级时要同时核对页码带、点击区与缩放视口，不能只挪贴图。
2. `ScenarioPageBuilder.java:41-59` 把「条件区 + 可达条目区」拼成同一块序列；`ScenarioFrameView.java:40-49` 把它放进可缩放文档。两种阅读任务被同一套缩放/平移交互绑定。
3. `ScenarioPageBuilder.java:86-94` 把物品名称和概率拼在同一文本行；长名称会占用概率的可读空间。`UiNode.Row` 当前是自然宽度行，没有固定右列（`client/ui/kit/UiNode.java:14-39`）。
   同类还用 `ScenarioPageBuilder.java:34` 的 12 项上限截断结果；滚动式结果页应优先展示全部已测得的可达条目，数量异常多时才按实测性能决定分段加载。
4. `ScenarioDetailPanel.java:167-175` 的重建门控先用旧 `input` 查询状态、再返回；场景或参数变化而目录 revision 与状态词不变时，**可能**保留旧标题/内容。此项是源码推断，实施首批须复现并修正，不能仅凭截图认定发生。
5. 场景列表宽度写死为 152，单行高 20（`ScenarioSelectionOverlay.java:43-46`、`:122-135`）；参数窗使用固定 276 宽且底部有固定提示槽（`ScenarioParamsOverlay.java:37-39`、`:199-210`）。这限制长本地化文本与小窗口阅读。

## 二、目的

### 2.1 玩家任务与成功标准

以「找到一张表 → 看懂当前是否能得到某物 → 比较一个场景 → 调整参数并计算 → 返回结果」为主路径。打开任何页后，玩家应先看到**当前对象、当前状态、下一步操作**，再按需展开细节。

- 场景页默认无需缩放或悬停，就能看见当前场景、计算状态、至少首屏结果的完整概率；完整长名称可通过明确的详情/提示读取，概率列始终可见。
- 「基准」说明它代表什么；「未计算、计算中、已缓存、失败」用文字加形状共同表达，失败提供下一步动作。
- 条件解释与结果清单各有入口或清楚分区；结果列表不因条件树长度消失在首屏。
- 场景选择支持快速比较当前/候选的名称与状态，长条件有可展开路径；参数窗先说明控件含义，确认与计算的关系明确。
- 鼠标、滚轮、Tab/Shift+Tab、Enter/Space、Esc 的路径一致；本地化到 `en_us`、`zh_cn` 后仍能阅读。

### 2.2 架构目标

- 在**宿主层**逐页接入已有 `UiDocument`、`UiScrollView`、`UiLinearLayout`、`UiControlGroup`、`UiFocusManager`、`OverlayLayer`；服务端目录、概率判定、网络协议与存档状态保持原有权威来源。
- 页面视图只读当前 `table + scene + params + 请求状态 + 目录 revision`，由一个明确的视图键触发内容重建；不在逐帧路径重建列表、节点或回调。
- 新通用需求先在一页验证；确实跨页复用后再扩展 kit 公开 API，并同步 `package-info.java`、`docs/dev/internals/ui-kit-api.md` 的契约和兼容记录。

### 2.3 明确不做（本轮范围外）

- 不改战利品表模拟算法、概率四态的服务端语义、签发场景顺序、请求/结果 payload 与玩家进度。
- 不为翻新另起一套与 UI kit 并行的通用框架，不把 `OverlayLayer` 或项目资源键塞进 kit。
- 不承诺本轮把独立的战利品表管理 Screen、物品交互 Screen、HUD 全部重做；只检查它们与笔记入口的衔接。
- 不把截图里的技术 tag 自动翻译成臆造的群系名；显示名来自可用本地化，缺失时保留原 ID 并提供解释。

## 三、技术原理

| 路线判断 | 已核实依据与等级 | 结论 |
|---|---|---|
| 为什么先改信息架构再批量替换控件 | 160×224 逻辑页尺寸（源码核实 `JournalLayout.java:10-17`）；截图 2、4 的主要问题是视口与信息拥挤（实机截图） | 先确定每页信息优先级、留白、滚动/分页语义，再选择组件。机械地把旧坐标换成 kit 不能解决可读性。 |
| 为什么场景页结果使用固定概率列 | 现有结果行拼接文本（源码核实 `ScenarioPageBuilder.java:86-94`）；`UiNode.Row` 不提供多列（源码核实 `UiNode.java:14-39`） | 先在宿主用 `UiLinearLayout` 落位「图标/名称/概率」，名称区单独裁剪/悬停阅读，概率区保持固定；若其他列表有同样需求，再抽取 kit 的通用行布局。 |
| 为什么保留条件树的放大能力 | 现有 `UiDocument`、`UiTransform`、`UiLightbox` 可浏览复杂树（源码核实 `ScenarioFrameView.java:20-49`、`ScenarioDetailPanel.java:203-217`） | 条件细节可继续进入灯箱；主场景页改成常规阅读与滚动视图，不让缩放成为读概率的前提。 |
| 为什么只迁移宿主层业务视图 | kit 的公开边界只允许依赖 Minecraft 客户端通用类型，不依赖项目包或 loader（文档核实 `docs/dev/internals/ui-kit-api.md`「依赖方向与可执行检查」） | 数据投影与本地化留在 `client/ui/panel` / `support`；kit 只提供测量、布局、控件、滚动、焦点等通用能力。 |
| 为什么显式区分「确认参数」与「计算」 | 当前确认参数不自动计算、请求由显式计算按钮发起（文档核实 `docs/dev/internals/journal-ui-internals.md`「场景详情页与模态交互」） | UI 文案与状态反馈必须说清：确认仅保存输入；点「计算」才会请求结果，避免误以为概率已刷新。 |

**必须遵守的边界**：`common/` 不导入 Fabric/NeoForge 类；服务端不引用客户端 UI；沿用已有 Event API/模态层，不引入新 Mixin；GUI 文案均有本地化 key 且同步 `en_us.json`、`zh_cn.json`；小窗口的逻辑坐标经 `JournalViewport` 转换，滚动、命中、tooltip 必须用同一坐标系；公开 kit 变更遵守兼容策略。

## 四、技术路线

### 4.1 目标阅读结构

维持书本双页与四个主 Tab。左页负责**找表与定位**，右页负责**看当前表**：介绍页给表概况，考古页给条目及获取状态，场景页给指定输入的结果与条件，日志页给历史。所有页沿用同一标题、状态、操作、内容、页脚的视觉顺序。

场景页在 160×224 右页内建议采用以下**逻辑布局草案**；数值仅是设计验证起点，不作为新硬编码常量：

```text
当前场景名（单行摘要）             状态词/图标
当前输入摘要（工具、幸运、次数；可进入参数）
[选场景] [参数] [计算]              ← 有可读名称的主操作
[结果] [条件]                      ← 默认结果；各自保留阅读位置
┌ 内容视口：自然大小、纵向滚动 ─────────┐
│ 结果：物品图标 | 可读名称 | 固定概率列 │
│ 条件：完整定义与层级，可进入放大查看   │
└──────────────────────────────────┘
                     原有页码/切场景导航
```

「结果」页按当前输入展示全部已测得的可达条目，并显示总数；未计算/失败时在内容区给清晰空态与操作，不显示旧概率。「条件」页说明基准与当前成立/不成立的条件；复杂树可打开现有灯箱。主视图的滚轮用于纵向阅读，灯箱内才用于缩放。切场景后保留同表场景选择，视图滚动位置按当前内容重置或按语义恢复，不能显示旧场景的结果。

### 4.2 关键类型与接入映射

| 目标职责 | 优先使用的现有 API | 宿主侧工作 |
|---|---|---|
| 内容文档/条件树 | `UiDocument`、`UiNode`、`TextMeasurer` | `ScenarioPageBuilder` 拆成结果投影与条件投影；只在视图键变化时重建。 |
| 结果行、摘要与动作 | `UiLinearLayout`、`UiControlGroup`、`UiControlStyle`、`TextScroll` | 按稳定 key 复用行控件；固定概率列，名称独立提示；按钮统一状态和文案。 |
| 内容滚动 | `UiScrollView` | 每个子视图管理自己的内容高度、偏移、滚动条；横向不靠整页缩放补救。 |
| 键盘与原生输入 | `UiFocusManager`、`UiFocusTarget` | 宿主按视觉顺序登记标题后操作、子视图、模态控件；幸运仍交给 `EditBox`。 |
| 场景与参数模态 | 既有 `OverlayLayer`、`ScenarioSelectionOverlay`、`ScenarioParamsOverlay` | 列表改为可读的摘要/详情层级；空提示不画背景；输入优先级与返回焦点沿用旧契约。 |
| 条件放大 | `UiLightbox`、`ScenarioExpandedOverlay` | 复用现有灯箱，只用于需要放大的条件树；避免页内第二套缩放按钮遮住正文。 |

优先不新增 kit API。若实施时证明需要通用「固定尾列的富文本行」或通用「分段阅读视图」，先在宿主验证至少两个使用处、明确测量/命中/裁剪契约，再扩充 kit；不能为了单个场景页增加携带战利品语义的组件。

### 4.3 视图数据流与状态边界

`ArchaeologyJournalClientState / ScenarioSimulationClientState` → 宿主构造轻量 `ScenarioView`（表、场景、参数、计算状态、条件、结果、版本键）→ `ScenarioDetailPanel` 选择结果/条件视图 → kit 排版渲染。点击「计算」仍调用现有请求；收到状态或目录变化后只重建受影响视图。视图键至少含 `tableId`、`sceneKey`、参数的 input key、目录 revision、结果/请求状态版本；不能只用状态词判断是否需要刷新。

重建时检查「标题/状态/结果/tooltip 来自同一输入」，并明确空态：无表、无场景、未计算、排队中、已缓存但零结果、失败、数据过期。目录更新或切表时关闭过期模态并重新校验选择；持久化继续交给现有 `JournalUiPreferencesStore` / `UiPanelRegistry`。

| P3：全书页逐页迁移 | 以同一验收表审查目录/搜索、介绍、物品网格、日志列表/详情；优先修真实可读性/命中问题，再迁移可复用的布局、滚动、控件与焦点。 | 每页对照迁移前功能清单：搜索/排序/收藏/追踪、分页、物品提示、日志分组/备注/复制/删除均可用；无因“换 API”而丢功能。 |

每阶段是一组可独立审查的改动。P1 的体验结果经实机确认后再推进 P3 的大面积迁移；若某页旧实现已满足体验指标，就保留它，不为统计 kit 覆盖率改写。

### 4.6 文档同步

完成一阶段即更新 `client-ui.md` 与 `journal-ui-internals.md` 中对应的真实行为；若新增公开 kit 入口，同步 `package-info.java`、`ui-kit-api.md` 的清单/兼容记录。阶段全部结束后在本文追加「九、实施结果」，将计划移入本地归档；最终机制以 `docs/dev/` 为准。

## 五、决策记录

| 编号 | 决策点 | 结论、备选与理由 |
|---|---|---|
| D1 | 翻新粒度 | 按玩家任务与页面分阶段；不一次替换整个 Screen。现有滚动、模态、灯箱已接入 kit，整体重写会扩大回归面。 |
| D2 | 场景页默认视图 | 结果优先，条件有独立清楚入口；不继续把两段强制堆进一个需缩放的框。截图 2、4 显示结果阅读被挤压。 |
| D3 | 结果概率呈现 | 固定尾列，不能把名称和概率拼成一个文本串；长名称仅在名称区滚动或展开。 |
| D4 | 场景定义 | 用玩家可读摘要作标题，完整原始定义仍可查；不把 tag ID 隐藏到无法核对，也不让原始 ID 占据主标题。 |
| D5 | 计算触发 | 保持现有显式「计算」语义；参数确认后显示「输入已更改，需计算」一类状态，避免旧结果被误读为新输入。 |
| D6 | kit 扩展 | 宿主先验证、跨页复用后才新增公开能力；不把模组专有数据、资源路径或网络逻辑放进 kit。 |
| D7 | 现有截图的解读 | 截图能证明视觉问题，不能证明缓存/同步 bug；`ScenarioDetailPanel` 早返回风险先列为待复现项。 |
| D8 | 后续修正记录 | 实施中若发现本计划的判断有误，在此表追加日期、原判断、证据与改判，不静默改写历史结论。 |
| D9 | 2026-09-27：重建门控风险复核 | 第 1.2 节第 4 点担心切换输入而 revision 未变。源码核实 `ScenarioSimulationClientState.select` 在选择实际变化时调用 `ArchaeologyJournalClientState.simulationChanged()`，因此该路径并不能证明旧实现会留脏内容；新实现仍显式比较 input key、目录 revision 与请求状态，缩小后续状态耦合风险。 |

## 六、风险与限制

| 风险 | 说明 | 处置 |
|---|---|---|
| 小页宽与多语言 | 160 逻辑像素内中文/英文长度差很大，扩大按钮可能压缩正文。 | 每处先做宽度预算；结果概率固定列，名称留独立区域；中英文都用实际字体测量。 |
| 旧状态残留 | 切场景/参数、网络回包或 `/reload` 可能让标题与结果版本不同。 | 统一视图键和状态投影，场景变化即清除不适用的当前结果；复现旧重建门控风险。 |
| 滚动与缩放冲突 | 主视图滚轮若继续缩放，玩家无法自然阅读长清单。 | 主视图纵向滚动；仅灯箱使用缩放，并在提示中写明。 |
| 全量迁移的功能回退 | 日志批量操作、网格子表入口、JEI 悬停等路径较多。 | 先列每页功能清单，再一页一页迁移；每阶段保留可回退的旧页面边界。 |
| kit 公开 API 稳定性 | 当前公开入口已有兼容约定，随意改签名会影响示例/宿主。 | 优先组合现有 API；必要改动走 `ui-kit-api.md` 的兼容与边界检查。 |
| 截图覆盖有限 | 四张图只覆盖 NeoForge、中文、两个场景与参数窗。 | 实施前补英文、Fabric、小窗口与其他页面的实机对照；未观察页只列待核验。 |

## 七、验证方式

**编译验证（开发执行）**：每阶段先用 IDEA MCP 检查改动 Java 文件的 error/warning（忽略 Markdown 格式），执行 `pwsh -File scripts/check-ui-kit-boundaries.ps1`（仅改 kit/宿主边界时），然后单次运行 `./gradlew build` 并等待结束；不新增 `test` 文件。仅修改本计划文档时，以链接/路径/事实核对为主，构建留到实际代码阶段。

**实机验证（用户执行）**：NeoForge 与 Fabric 各走以下主路径；保留迁移前后同 GUI scale 截图，重点看「一眼可读」与输入行为，而非只看编译通过。

1. 中文、英文各打开基准和长名称场景；标题、当前状态、结果概率、完整定义均可找到，静止首屏不因截断而误解。
2. 选一个有 12 项以上结果及复杂条件的表：滚轮读完结果，概率列不被名称、滚动条、页脚或控制按钮盖住；进入灯箱能读条件全树。
3. 在未计算、计算中、成功、零结果、失败/过期状态之间切换；旧场景的数字不出现在新场景的标题下，失败文案给出可执行动作。
4. 修改工具、幸运、抽样档位、附魔等级；取消不生效，确认只改输入，点击计算后结果与当前输入一致；非法幸运值有可见提示。
5. 用鼠标、滚轮、Tab/Shift+Tab、上下键、Enter/Space、Esc 走场景列表与参数窗；外部点击行为、焦点恢复、tooltip 唯一性与现有契约一致。
6. 搜索、排序、收藏/追踪、网格子表跳转、日志分组与详情、备注/复制/删除逐项核对；关闭重开、切表、resize、断线重进后偏好与页内位置合理。
7. 在较小 GUI 尺寸/较高 GUI scale 下，确认整书不出屏、模态可操作、鼠标命中与视觉位置一致；检查无持续每帧重建或滚动卡顿。

## 八、待确认项

- P0 实机量测后确定场景页采用「结果/条件」双视图还是同页可折叠分区；推荐双视图，因为固定页高下更能保证结果首屏可读。两者都必须满足第二章指标，不能仅凭草图定稿。
- 若需要更大的场景选择窗，先确认在最小支持逻辑画布内的可用宽度与灯箱/书页遮挡；推荐居中模态并给完整定义独立滚动区。
- 其他页面的迁移优先级由 P0 的逐页体验清单决定，避免把未经观察的旧绘制方式直接列为缺陷。

## 九、实施结果

### 2026-09-27：首批落地（P0–P2）

- **P0**：核对输入变化时的 revision 路径，修正第 1.2 节的推断；详情页重建改为同时比较 input key、目录 revision、请求状态。修复 `UiFocusManager` 多次更新时重复保留目标的问题；为结果、条件分开保存滚动偏移，并在字体/布局重建时恢复。
- **P1**：场景页改成结果默认、条件独立切换。结果列表去掉 12 项截断，物品图标、长名称和概率各有自己的位置；极长区间概率在固定列内悬停滚动，完整值可由提示读取。图标接入原有物品 tooltip/JEI 悬停链路，滚轮纵向滚动。条件树按自然字号滚动，复杂树仍可在灯箱中缩放。未计算、请求中、失败及零结果有独立内容状态。
- **P2**：场景列表改为居中双行卡片，显示短名、计算状态和条件摘要，完整定义放在 tooltip；网格与场景页统一状态投影。参数窗不再绘制空提示横带，抽样次数补单位，确认提示说明需另按「计算」。中英文文案同步更新。
- **文档与 API**：`client-ui.md` 与 `journal-ui-internals.md` 已按现行机制更新。宿主复用现有 UI kit 组件，公开 API 未新增；`UiFocusManager` 的目标更新属于原契约内修正。
- **构建记录**：`./gradlew build` 首轮通过（common、Fabric、NeoForge）；Javadoc 暴露 `UiLightbox` 旧注释中的未转义尖括号，已修正并安排复核。UI kit 边界脚本、JSON 解析及中英文 key 对齐检查通过。
- **仍待核验**：四张原截图只有改造前的 NeoForge 中文画面。P1/P2 的中英文长文案、超过 12 项结果、鼠标/键盘、缩小窗口、Fabric 和偏好恢复，需要按第七章在游戏中核验。P3 其他页面迁移以这轮体验反馈及逐页观察为入口，避免盲目改写已有功能。

### 2026-09-27：首轮实机反馈修正

用户的 NeoForge 截图 `13.17.56.png`、`13.18.38.png` 显示两个回归：列表把含目标场景引用的缓存判为「已计算」，但考古网格仍显示 `?`；模态期间下层 tooltip 已停用，悬停高亮仍会跟着鼠标变化。修正为三处共用同一场景缓存来源，网格仅投影目标场景的明确物品/子表概率引用；屏幕向下层自绘面板与原生控件传入视口外鼠标坐标，浮层继续接收真实坐标。仍需用户实机复核这两条路径。

### 2026-09-27：合集解锁与子表定位

用户的 NeoForge 截图 `13.40.45.png` 显示未解锁时 tag/子表合集仍公开名称、概率；另有子表同时是分类根表时，点击父表子表入口会落到并列根表行。修正为合集内任一物品发现后才公开入口信息，子表预览从完整后代闭包取已发现成员；跳转先展开当前父表路径，再选它下面的子表行。仍需实机复核未解锁态、首次发现后的更新和根表/子表同名节点定位。
