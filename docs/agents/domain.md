# 领域文档

## 布局与读取

本仓库采用 single-context 布局：

- 根目录 `GLOSSARY.md`：领域术语。
- `docs/adr/`：已确认落地的架构决策；首个 ADR 确认后按 `0001-<slug>.md` 顺序创建。

开始非平凡开发任务前，先阅读 [开发者文档导航](../dev/README.md)。探索领域概念或架构决策时，读取术语表及与当前任务相关的 ADR。

`GLOSSARY.md` 是当前术语事实源。没有与当前任务相关的 ADR 时，直接继续任务；只有确认了需要长期保留的架构取舍才创建 ADR。

## 术语

Issue 标题、重构建议、问题假设及其他输出中的领域概念，使用术语表定义的名称。

需要的概念尚未收录时，先核对项目代码与文档；确有术语缺口时，通过 `domain-modeling` 补充已确认的定义。

## 决策一致性

方案与现行 ADR 冲突时，指出对应文件、冲突点及重新评估理由。

当前实现与机制以 `docs/dev/` 对应权威文档为准。ADR 仅记录已确认落地的决策；过时决策移入 `.local/archive/`，命名与索引更新遵循 [Issue 追踪器](issue-tracker.md)的归档约定。
